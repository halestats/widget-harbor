# iStoreOS 升级到 v1.3.0

保留 `/opt/widget-harbor` 原目录、`.env` 和 `data`。不要重新安装，不要删除目录。此版本包含临时挂载数据库备份的修复，无需额外 sed 补丁。

上传 `widget-harbor-v1.3.0.tar.gz` 至 `/opt/` 后，在 iStoreOS 终端执行：

```sh
(
  set -eu
  cd /opt
  stage=$(mktemp -d /opt/widget-harbor-update.XXXXXX)
  tar -xzf widget-harbor-v1.3.0.tar.gz -C "$stage"
  sh "$stage/widget-harbor/scripts/upgrade.sh" /opt/widget-harbor
)
```

`mktemp` 命令保持一整行。脚本先备份配置、源码和数据库，然后构建镜像，只重建本应用。原密码、头像、模块、合集、域名和允许的内网地址保留。健康检查通过后刷新网页。

## 合集来源与刷新

合集卡片标记“导入”或“自建”，卡片提供“刷新”；编辑窗口提供远程订阅来源、每天自动刷新开关和“保存并刷新”。这里填写原 `.rex`/`.fwd` 订阅地址，不是单个模块的 raw 地址。公开下载仍只允许 HTTP/HTTPS 的 80/443 端口。

- 导入合集：同步上游成员与模块内容。按来源 URL、其次按唯一模块 ID 匹配，保留本地模块 ID 与订阅直链。上游新增成员会加入；上游移除成员只从此合集移出，不删除模块库文件，不破坏自建合集的引用。合集标题、描述和图标保留本地设置。
- 自建合集：只刷新当前选中的远程模块。能确定原订阅时，先读来源订阅的当前元数据，再下载对应模块；其余远程模块从自身来源下载。本地上传模块保持不变，不向自建合集添加上游新成员。
- 内容下载和校验完成后一次提交。下载失败、提交前取消或期间发生编辑冲突时保留原模块与成员。刷新状态及错误在编辑窗口显示。
- 每天自动刷新表示距离上次尝试满 24 小时后触发，应用每分钟检查一次；成功和失败都会记录尝试时间，避免反复请求上游。手动刷新会重新计算下一次时间。任务由容器内进程执行，不需要宿主机 cron。
- 新链接导入的合集默认开启每天刷新；自建合集默认关闭，可在编辑窗口开启。手动开启且从未刷新过的合集会在下一次检查时开始首次刷新。
- 时间、来源、类型和开关保存在数据库，重启后保留；重启中断的下载不会部分覆盖模块。JSON 备份也包含这些配置与时间。

旧版本未保存合集来源，只有当自动生成的导入合集内所有模块的 `source_group` 指向同一订阅 URL 时才能自动补回。不能确定时保留空白，请手动补填原订阅链接并保存。旧的 `import-…` 合集会保留“导入”标记；这不代表已知道其远程地址。

## 描述缺失的边界

客户端可能读取甚至解密模块源码中的描述，而模块库展示保存的元数据。新版支持普通字符串和不含插值的模板字符串描述，启动时会从已存普通脚本补回空描述，已有非空描述保留。刷新时也不会因为源码缺少字段而抹掉原有名称、作者和描述。

已确认某些上游文件是 `REXENC` 加密格式，上游订阅的描述又为空。服务器不解密这类脚本，无法从密文恢复客户端显示的说明；它会显示“加密模块，来源未提供描述”，并允许手动填写描述或等待上游补充。加密文件原字节保留，不提供在线源码编辑。

## 列表与手机布局

- 每个来源分组右侧有独立的全选/取消全选按钮，只影响该分组当前可见结果。
- 手机操作区统一为两列布局，排序和操作按钮均为 42px 高、同列宽。桌面保留一行布局。

## 备份与回退

升级备份位于项目 `backups/upgrade-时间-进程号/`。新增的同步配置表不改变原模块内容。回退旧版本前保留本次备份；旧版本不会运行每日刷新。

```sh
cd /opt/widget-harbor
backup='替换为升级脚本打印的备份目录完整路径'
test -f "$backup/image-id.txt" && docker tag "$(cat "$backup/image-id.txt")" widget-harbor:local &&
docker compose -f docker-compose.yml -f docker-compose.istoreos.yml up -d --no-build --no-deps hub
```

不要清理全局镜像或重启 Docker、Lucky、WireGuard。
